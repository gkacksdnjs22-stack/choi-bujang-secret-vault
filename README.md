브라우저의 로그인과 메모 CRUD를 `/api/auth` 및 `/api/notes`로 모았습니다. Supabase 키와 직접 데이터 요청은 화면 묶음에서 제거했고, 서버 함수만 Supabase에 접근합니다. `aleph.config.json`에는 원본 자료 API 주소와 허용 경로를 기록하며, 배포 식별 파일에도 `allowedRoutes`를 포함합니다.

로컬 확인: 화면 파일에서 Supabase 키·URL·SDK 문자열이 검색되지 않았고, 3·4단계 인증 거부 및 소유자 검사도 다시 통과했습니다. 실제 배포 로그인과 5단계 심판 제출은 아직 미실행입니다.

## 자체 실습 서버 연결 (운영 ALEPH 연결과 별개)

자체 서버 기준으로 진행합니다. 통합 검증 명령은 `npm run test:server`입니다. 배포 화면의 「메모 접근 확인 → 조회 권한 확인」에서는 로그인 계정의 본인 메모는 200, 타인 메모는 403이어야 합니다. 실제 양방향 조회는 확인했고, 수정·삭제 및 권한 회수는 활성 판정 흐름과 실제 API 함수를 가상 DB에서 통합 검증했습니다.

로그인한 학생은 자료실의 「이 브라우저 접속 등록 → 접속 정보 확인」에서 자신의 연결 정보만 조회합니다. `/api/device`는 로그인 없이 조회하거나 등록을 변경할 수 없습니다. 서명된 Secure·HttpOnly·SameSite=Strict 쿠키는 브라우저를 구분하며 하드웨어 기기 인증은 아닙니다. 계정 전환 시 사용자 식별자는 달라지고 브라우저 식별자는 유지됩니다. 쿠키 만료 또는 서버 키 교체 시 다시 관리자 등록이 필요합니다.

메모·공지 API에 자체 판정 흐름을 연결했습니다. `RESOURCE_POLICY_MODE=enforce`일 때 현재 관리자 연결, 만료, 자료 소유자/강사 권한을 확인합니다. 미설정은 `off`로 기존 API 소유자 검사를 유지합니다. 실제 A/B 계정과 현재 브라우저의 24시간 등록을 확인했고, vercel.json에서 enforce 배포를 설정했습니다. 관리자 등록부를 앱 서버가 직접 수정하는 API는 만들지 않았습니다. 운영 ALEPH 엔진의 호출 및 심판 통과는 미검증입니다.

검증: `node scripts/check-server-policy.mjs`를 포함한 로컬 가상 DB 검증. 실제 A/B 등록은 완료했습니다. 배포 화면의 「메모 접근 확인」은 현재 로그인 계정으로 읽기 요청을 보내 HTTP 응답 코드만 표시합니다. 운영 배포의 실제 응답 검증은 별도로 기록합니다.
