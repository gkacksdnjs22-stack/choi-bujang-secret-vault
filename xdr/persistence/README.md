# 몰래 심어진 프로그램 보너스

공식 `ChoiTimo/aleph-defense-starter` 저장점 `2cd777b452525b95e29f12f2c76d9190a594ec23`의 `xdr/fixtures/persistence.json`을 그대로 가져왔습니다. SHA-256은 `1dd5adeab11f8b222ec5f4880955a4f428a29728098e139bcd9a3fc4b0f970d3`입니다. 24건은 Wazuh 모양의 수업용 경보이며 실제 PC 침입 로그가 아닙니다. 서비스 생성·예약 작업 설치·프로그램 실행은 하지 않습니다.

## 과제 지침과 구현

| 지침 | 구현·확인 |
| --- | --- |
| 제작1: 경보 읽기 | read-alerts는 시각·출발 주소·가상 계정·수준·설명 5개 필드 24줄을 추출하며 JSON/따옴표 형태의 비밀값도 가립니다. |
| 제작2: 근거 패턴 | 서비스 변경은 [T1543](https://attack.mitre.org/techniques/T1543/), 예약 작업은 [T1053](https://attack.mitre.org/techniques/T1053/), 안내에 있는 시작 폴더 신호는 보충 근거 [T1547.001](https://attack.mitre.org/techniques/T1547/001/)을 확인했습니다. |
| 제작3: 단독 판단 | decide.mjs 맨 위 상수로 패턴을 옮겼으며 import·파일 입출력·외부 호출이 없습니다. action/confidence/reason만 반환하고 경보 번호로 정답을 고르지 않습니다. |
| 제작4: 알림과 차단 | respond는 block 후보만 확인된 기기에 연결하며 만료·근거 경보 번호를 붙입니다. block/alert만 알림 로그에 쌓고 기존 deny/step_up을 보존합니다. |
| 제작5: 실행 기록 | result.json은 block8 / alert8 / record8, 정상8건 오차단0입니다. |

서명 없는 서비스 생성/실행 파일 변경과 임시 실행 파일, 원격 반복 등록, 낯선 작업의 임시 실행 파일, 새 자동 시작 항목 등 여러 신호를 경보 수준과 함께 대조합니다. 임시 실행 파일 하나·서명 확인 안 됨·서비스 설명만 변경 같은 불완전 신호는 알림으로 남깁니다. 과제의 0.85/0.5 분기값 외 세부 확신도·수준 조합은 로컬 정책이며 MITRE가 정한 숫자가 아닙니다. 보충 T1547.001은 과제의 시작 폴더 신호를 설명하는 근거로만 사용합니다.

## 기기 격리 연결

`respond({alerts, decideBase, resolveDevice, outputDirectory, clock, logFile})`의 `resolveDevice(alert)`는 서버가 확인한 등록부 조회 함수여야 하며 `{verified:true, deviceId}`를 반환해야 합니다. 경보의 공통 PC 이름이나 출발 IP를 기기 ID로 단정하지 않습니다. 기기 ID는 판정 계약의 16자리 소문자16진수 형식입니다. 연결이 없거나 확인되지 않은 값, 잘못된 ID, 중복 경보 번호는 로그·규칙 파일 쓰기 전에 거부합니다.

격리 규칙은 확인된 해당 기기의 접속 전체에 15분 동안 적용합니다. 따라서 격리된 PC의 평범한 요청도 격리 동안 거부되며, 다른 정상 기기는 허용됩니다. 만료되면 기본 판정으로 돌아갑니다. 기본 판정의 이미 내려진 거부·추가 인증은 덮어쓰지 않습니다. 현재 사용 중인 `policy_denied` 응답 코드를 기본값으로 쓰며, 운영 적용 전에 추가 규칙 ID를 운영 등록부와 대조해야 합니다.

시험은 명시적인 가상 등록부로 기기A/B를 구분해 실제 기본 판정 함수를 호출했습니다. 이 가상 등록부는 경보의 IP·이름에서 실제 기기를 알아낸 결과가 아닙니다. 후보 파일은 `liveConnected:false`로 저장하며 운영 사건 전달·실접속 격리 연결 완료로 주장하지 않습니다. 기본 판정기와 이전 보너스는 수정하지 않았습니다.

## 두 차례 검토와 실행

1차는 이어받기·제작1~5·제출 전 확인과 파일·패턴 근거·단독 실행·출력 형식을 대조했습니다. 2차는 원본24건과 별도 경계 입력을 실행했습니다. 애매한8건의 수준만 높여도 차단되지 않음, 수업 설명/정상 사건 보존, 비밀값 가림, 중복 번호·잘못된 기기 연결 거부와 기존 파일 보존, 다른 정상 기기 허용, 기존 deny/step_up 보존, 만료 뒤 허용을 확인했습니다. 원본 경보 지문은 변하지 않았습니다.

검토: `node scripts/check-xdr-persistence.mjs`

결과 재생성: `npm run xdr:run -- persistence`

과제 화면에서 ‘몰래 심은 프로그램 → 과제 보기’를 누릅니다. 정상 수업 경보는 record, 애매한 변경은 alert, 명확한 복합 신호는 block입니다. 검증은 수업용 입력과 로컬 연결 시험이며 심판 통과를 뜻하지 않습니다. 아직 과제에 제출하지 않았습니다.
