# 자료 빼돌리기 보너스

공식 `ChoiTimo/aleph-defense-starter` 저장점 `2cd777b452525b95e29f12f2c76d9190a594ec23`의 원본 `xdr/fixtures/exfiltration.json` 30건을 그대로 가져왔습니다. SHA-256은 `1b04986dc31fd46837f6f587c3a113b876c601746217f856d13b4b958abeb0aa`입니다. 경보는 수업용 가상 입력이며 문서용 목적지로 실제 파일을 보내지 않습니다.

## 지침과 구현 대조

| 지침 | 구현·검증 |
| --- | --- |
| 제작1: 경보 읽기 | read-alerts는 시각·출발 주소·가상 계정·수준·설명 다섯 필드만 30줄 출력하고 비밀값을 가립니다. |
| 제작2: 패턴 근거 | T1041/T1048을 확인하고 낯선 목적지·큰 전송·반복·업무 밖 압축 반출·다른 통로의 복합 신호를 정리했습니다. |
| 제작3: 단독 판단 | decide.mjs 맨 위 패턴 상수, decide(alert) 하나, action/confidence/reason 세 항목. import·입출력·외부 호출 없이 즉시 계산합니다. |
| 제작4: 판정기 연결 | block만 서버 확인 반·프로젝트·실제 목적지의 15분 거부 후보로 연결하고 만료·근거 ID를 붙입니다. alert/block만 알림 로그를 추가합니다. |
| 제작5: 경보 재생 | result.json은 block10 / alert10 / record10, 정상10건 오차단0입니다. |

근거는 [T1041](https://attack.mitre.org/techniques/T1041/)의 명령 통로를 통한 유출과 [T1048](https://attack.mitre.org/techniques/T1048/)의 다른 프로토콜을 통한 유출입니다. 경보의 크기·목적지·시간·반복·압축은 탐지 신호이며 실제 C2/프로토콜이나 파일 유출을 새로 확인한 증거는 아닙니다. 0.85/0.5는 과제 지정, 50MB·50자료·5반복·규칙 수준 및 세부 확신도는 로컬 정책이며 MITRE가 정한 수치가 아닙니다. 작은 전송·압축 생성만·실패·불완전한 반출·평소 대비 일회성 증가는 alert로 남기고 정상 읽기·저장·동기화는 record입니다. 경보 ID·가상 계정·주소별 정답 목록을 쓰지 않습니다.

## 목적지 거부 연결

`respond({alerts, decideBase, resolveDestination, resolveRequestDestination, outputDirectory, clock, logFile})`의 두 연결 함수는 서버 구성에 속합니다. `resolveDestination(alert)`는 사건과 보호 범위를 확인해 `{verified:true, classId, projectId, destinationAddress}`를 반환해야 합니다. 실제 목적지는 경보의 dstip와 일치해야 하며 출발 IP를 목적지로 대신하지 않습니다. 후보에는 원문 경보·계정·파일 내용이 없습니다.

`resolveRequestDestination(request)`는 엔진이 확인한 요청의 실제 전송 목적지를 같은 범위로 반환해야 합니다. 브라우저 본문의 목적지나 임의 `verified:true`를 신뢰하는 연결 함수로 만들면 안 됩니다. 현재18필드 판정 계약에는 목적지 필드가 없어 별도 서버 연결 인자로 받고, 계약에 새 필드를 덧붙이지 않습니다. 두 번째 호출 인자로 목적지 문맥을 주입해도 사용하지 않습니다. 신뢰할 수 있는 목적지 연결을 얻지 못하거나 요청 범위와 다르면 연결 오류를 반환하므로 운영 호출자는 fail closed로 처리해야 합니다.

같은 반·프로젝트의 해당 목적지는 15분 동안 거부하고 다른 목적지나 다른 범위는 이 규칙으로 막지 않습니다. 원래 판정의 deny/step_up은 보존하고 allow에만 추가 확인을 적용합니다. 만료 뒤 기본 판정으로 돌아갑니다. IP는 포트·URL을 받지 않고 IPv4/IPv6를 검증하며 같은 IPv6 표기를 정규화합니다. 새 규칙 ID는 운영 등록부와 대조해야 하며 기존 policy_denied 코드를 기본값으로 사용합니다.

후보 파일은 `liveConnected:false`입니다. 시험은 가상 목적지 등록부와 요청ID에 연결한 로컬 전송 문맥으로 실제 기본 판정 함수를 호출한 결과입니다. 실제 운영 사건 전달·외부 전송 감시·방화벽 적용을 완료했다는 뜻이 아닙니다. 기존 판정 규칙·API·다른 보너스는 변경하지 않았습니다.

## 두 차례 검토

1차는 이어받기·제작1~5·제출 전 확인·실패/되돌림 안내와 원본·패턴·단독 출력·계약을 대조했습니다. 2차는30건, ID/계정/주소 변경, 원본 불변·비밀값 가림·단독 로드·2초 제한·임계값과 잘못된 숫자, 애매한10건 수준 상향을 시험했습니다. 정상 목적지 허용, 여러 기기·주체의 해당 목적지 거부, 반·프로젝트 범위, deny/step_up 보존, 만료, 확인되지 않은 목적지·주소 불일치·중복·불완전 판단의 파일 보존을 검증했습니다. IPv6 동일 표기와 잘못된 URL/포트·인터페이스 표기도 확인했습니다.

검증: `node scripts/check-xdr-exfiltration.mjs`

결과 재생성: `npm run xdr:run -- exfiltration`

알림·거부 후보 예제 만들기: `node scripts/check-xdr-exfiltration.mjs --write-example` (로컬 가상 연결이며 실행마다20줄 알림이 추가됩니다.)

화면에서는 ‘자료 빼돌리기 → 과제 보기’를 누릅니다. 정상10건은 record, 불완전10건은 alert, 명확한10건은 block입니다. 정상 목적지는 allow, 유효한 거부 후보 목적지는 deny이고 만료 뒤 기본 정책으로 돌아갑니다. 아직 과제 제출 전이며 로컬 검증을 심판 통과로 주장하지 않습니다.
