# 권한 가로채기 보너스

공식 `ChoiTimo/aleph-defense-starter` 저장점 `2cd777b452525b95e29f12f2c76d9190a594ec23`의 원본 `xdr/fixtures/privilege.json` 26건을 그대로 가져왔습니다. SHA-256은 `e5e4b41e81138c79de7a62ad23859ce166cbf078fd8f9a2bac54a79e6f547a85`입니다. 경보는 수업용 가상 입력이며 실제 PC 권한이나 계정 그룹을 변경하지 않습니다.

## 지침과 구현 대조

| 지침 | 구현·검증 |
| --- | --- |
| 제작1: 경보 읽기 | read-alerts는 시각·출발 주소·가상 계정·수준·설명 다섯 필드만 26줄 출력하며 비밀값을 가립니다. |
| 제작2: 패턴 근거 | T1068/T1078을 확인하고 관리자 그룹 변경·새 관리자 명령·시간 밖 권한 사용의 복합 신호를 정리했습니다. |
| 제작3: 단독 판단 | decide.mjs 맨 위 패턴 상수, decide(alert) 하나, action/confidence/reason 세 항목. import·입출력·외부 호출 없이 바로 계산합니다. |
| 제작4: 판정기 연결 | block만 서버 확인 주체에 15분 거부 후보로 연결하며 반·프로젝트 범위, 만료, 근거 경보 ID를 붙입니다. alert/block만 알림 로그를 추가합니다. |
| 제작5: 경보 재생 | result.json은 block9 / alert8 / record9, 정상9건 오차단0입니다. |

패턴 근거는 [T1068](https://attack.mitre.org/techniques/T1068/)의 권한 상승 악용과 [T1078](https://attack.mitre.org/techniques/T1078/)의 정상 계정 악용입니다. 이번 경보는 상승·그룹·명령 사용의 탐지 신호이며 특정 취약점 악용을 확인한 증거는 아닙니다. 수업 취소·그룹 설명 변경·실패한 명령·일반 그룹 추가·한 번의 권한 상승 등 불완전한 신호는 alert로 남깁니다. 관리자라는 계정 이름이나 주소만으로 차단하지 않습니다. 0.85/0.5 분기는 과제 지정, 세부 확신도·수준 조합은 로컬 정책이며 MITRE의 수치가 아닙니다.

## 계정 세션 거부 연결

`respond({alerts, decideBase, resolveSubject, outputDirectory, clock, logFile})`의 `resolveSubject(alert)`는 서버가 확인한 신원 연결 함수입니다. `{verified:true, classId, projectId, subjectId}`를 반환해야 하며 subjectId는 엔진 발급자·반·프로젝트를 묶은 가명 주체입니다. 경보의 srcuser, Supabase UUID, IP, PC 이름 또는 브라우저가 주장한 값을 subjectId로 직접 사용하지 않습니다. 실제 요청 계약에 role·identity·session 같은 새 필드를 추가하지 않습니다.

규칙은 같은 반·프로젝트·주체의 접속을 15분 거부합니다. 같은 계정의 다른 기기도 거부되지만, 같은 기기의 다른 정상 계정 및 다른 반·프로젝트 주체는 이 규칙에 의해 거부되지 않습니다. 기본 판정의 기존 deny/step_up을 보존하고 allow에만 추가 확인을 적용하며, 만료 뒤 기본 판정으로 돌아갑니다. 이 처리는 토큰 자체를 삭제하거나 인증 발급자의 세션을 영구 폐기하는 동작이 아닙니다. 운영 세션 회수는 사건 전달·확인된 주체 연결·규칙 등록을 연동한 뒤 별도로 확인해야 합니다.

시험은 가상 이름과 가명 주체를 명시한 로컬 등록부로 실제 기본 판정 함수를 호출했습니다. 후보 파일은 `liveConnected:false`입니다. 이 가상 등록부를 실제 계정 연결이나 운영 세션 회수 완료로 주장하지 않습니다. 기존 판정 규칙·소유권 API·다른 보너스는 변경하지 않았습니다. 잘못된 연결·중복 경보·미완결 판단은 로그와 후보 파일 쓰기 전에 거부합니다. 읽기용 표시 모듈은 decide가 불러오지 않습니다.

## 두 차례 검토

1차는 이어받기·제작1~5·제출 전 확인·실패/되돌림 지침과 각 파일·원본·패턴·계약을 대조했습니다. 2차는 26건, 경보 번호/계정/주소 이름 바꾸기, 단독 파일 로드, 임계값·출력·2초 제한, 애매한8건 수준 상향, 취소/미실행/잘못된 그룹/낮은 반복 횟수, 정상 이벤트 보존, 비밀값 가림을 실행했습니다. 계정별·기기 간·반/프로젝트 간 범위, deny/step_up 보존, 만료, 잘못된 신원 연결과 중복·불완전 판단의 파일 보존도 확인했습니다.

검증: `node scripts/check-xdr-privilege.mjs`

결과 재생성: `npm run xdr:run -- privilege`

로컬 가상 등록부로 알림·후보 예제 만들기: `node scripts/check-xdr-privilege.mjs --write-example` (실행마다 alert/block 로그 17줄이 추가됩니다.)

화면에서는 ‘권한 가로채기 → 과제 보기’를 누릅니다. 정상9건은 record, 불완전8건은 alert, 명확한9건은 block입니다. 다른 정상 주체는 allow, 유효한 거부 후보에 해당하는 주체는 deny이며 만료 뒤 기본 정책으로 돌아갑니다. 아직 과제에 제출하지 않았고 로컬 검증은 심판 판정을 대신하지 않습니다.
