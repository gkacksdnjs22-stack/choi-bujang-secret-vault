## 실제 자료실에서 확인한 결과

배포 커밋 `f612916`에 등록된 A/B 계정으로 로그인하고 화면의 읽기 전용 「메모 접근 확인」을 실행했다. 로그인 토큰은 브라우저에서만 사용했으며 이 기록에 계정 식별자나 메모 본문을 넣지 않았다.

| 로그인 | 대상 | 실제 응답 |
|---|---|---|
| A | A 소유 메모 | 200, 조회 허용 |
| A | B 소유 메모 | 403, JSON 오류 `policy_denied` |
| B | B 소유 메모 | 200, 조회 허용 |
| B | A 소유 메모 | 403, JSON 오류 `policy_denied` |

각 계정의 목록에는 본인 메모만 표시됐다. 관리자 접속 등록부의 사용자 연결은 24시간 동안만 유효하며, 관리자 역할이나 강사 권한을 부여하지 않는다. 등록 기간이 끝나거나 서명 쿠키가 바뀌면 새 접속은 거부된다.

동적 경로에 동일한 자료 ID가 쿼리로 함께 전달되는 정상 요청은 정규화했다. 서로 다른 ID, 중복 쿼리와 기능 경로는 거부한다.

## 로컬 검증

`node scripts/check-server-policy.mjs` — 서명 쿠키, 사용자 연결, 등록 회수, 목록·추가 경로.

`node scripts/check-ownership-decider.mjs` 및 `node scripts/check-resource-grants.mjs` — 현재 DB 소유자에 따른 허용·거부, 만료 및 학생 공지 쓰기 거부. 가상 DB 시험이다.

`node scripts/check-step8.mjs` — 자료 구역, 정확한 경로, 동적 ID 정규화, 소유자 및 강사 검사. 가상 DB 시험이다.

실제 메모 수정·삭제, 실제 강사 쓰기 및 등록 회수 시험은 이번 배포에서는 실행하지 않았다. 앞 단계의 오래된 `test:r5`에는 현재 서버 자료실 구조와 맞지 않는 두 단언이 남아 있으므로 전체 테스트 통과로 표현하지 않는다.

## 운영 ALEPH 연결과 남은 사항

자체 API는 검증된 Supabase 로그인과 서버 서명 쿠키를 바탕으로 현재 `principal_bindings` 및 소유권을 대조하고, `decideOwnedResource → createDecider`를 호출한다. 배포 설정은 `RESOURCE_POLICY_MODE=enforce`다.

ALEPH가 별도로 호출하는 `decide(request)`는 이 DB 연결을 호출하지 않는다. 자체 서버의 사용자·프로젝트 식별자와 ALEPH 엔진의 식별자가 같다는 근거도 없다. 실제 연결에는 운영 엔진의 검증된 주체와 이 자료실 계정의 연결 방식, 신뢰된 권한 입력 경로 및 허용 이유 코드 확인이 필요하다. 이 정보를 임의 상수나 브라우저 입력으로 대신하지 않는다.

따라서 위 결과는 실제 자료실 API 방어 증거이며 ALEPH 운영 연결 또는 심판 통과 증거는 아니다. 재제출은 하지 않았다.
