동적 경로에 동일한 자료 ID가 쿼리로 함께 전달되는 정상 요청은 정규화했다. 서로 다른 ID, 중복 쿼리와 기능 경로는 거부한다.

## 운영 ALEPH 연결과 남은 사항

자체 API는 검증된 Supabase 로그인과 서버 서명 쿠키를 바탕으로 현재 `principal_bindings` 및 소유권을 대조하고, `decideOwnedResource → createDecider`를 호출한다. 배포 설정은 `RESOURCE_POLICY_MODE=enforce`다.

ALEPH가 별도로 호출하는 `decide(request)`는 이 DB 연결을 호출하지 않는다. 자체 서버의 사용자·프로젝트 식별자와 ALEPH 엔진의 식별자가 같다는 근거도 없다. 실제 연결에는 운영 엔진의 검증된 주체와 이 자료실 계정의 연결 방식, 신뢰된 권한 입력 경로 및 허용 이유 코드 확인이 필요하다. 이 정보를 임의 상수나 브라우저 입력으로 대신하지 않는다.

따라서 위 결과는 실제 자료실 API 방어 증거이며 ALEPH 운영 연결 또는 심판 통과 증거는 아니다. 재제출은 하지 않았다.

## 자체 서버 실습 기준의 완료 상태

사용자가 운영 ALEPH 연동을 기다리지 않고 자체 서버 기준으로 진행하도록 결정했다. 자체 서버에서는 검증된 로그인 → 서명 쿠키 → 현재 접속 등록부 → 현재 소유자/강사 권한 → 판정기 → 최종 API 검사 흐름을 구현하고 배포했다.

`npm run test:server`는 `RESOURCE_POLICY_MODE=enforce` 상태에서 실제 메모·공지 API 함수를 호출한다. 로그인 발급자와 DB만 가상화한다. 본인 CRUD, 타인 조회·수정·삭제 차단 및 DB 자료 불변, 소유자·역할 위조 거부, 계정과 다른 브라우저 연결 차단, 접속 등록 회수, 강사 권한 회수 및 DB 장애 시 차단을 확인했다. 실제 DB 쓰기 시험이나 운영 ALEPH 검증으로 보고하지 않는다.

자체 서버 실습의 권한 연결과 위 검증은 완료했다. 운영 ALEPH 연동은 이 범위의 선행 조건으로 취급하지 않으며, 과제 심판의 평가와는 별개다. 실제 접속 등록은 24시간 만료 조건을 유지한다.
